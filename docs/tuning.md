# 하이브리드 가중치 튜닝

`src/router/menu-router.js`의 `DEFAULT_VECTOR_WEIGHT`를 어떻게 정했는지 기록한다.
임의로 고른 값이 아니라 실측으로 정했다.

## 측정 방법

`scripts/eval-coverage.js`에 `VECTOR_WEIGHT` 환경변수를 주어 같은 시험셋을 세 번 돌렸다.

```
VECTOR_WEIGHT=0.5 node scripts/eval-coverage.js
VECTOR_WEIGHT=0.7 node scripts/eval-coverage.js
VECTOR_WEIGHT=0.9 node scripts/eval-coverage.js
```

시험 발화는 인덱스에 넣지 않은 held-out 절반이다(`data/heldout.json`).
학습에 쓴 발화로 시험을 보면 100%가 나오고 그 숫자는 아무것도 증명하지 못한다.

## 결과

| vector : lexical | 시험 발화 | Top-1 | Top-3 | 계열사 오분류 | 산출물 |
|---|---|---|---|---|---|
| 0.5 : 0.5 | 10,487 | 11.8% | 21.0% | 39.4% | `data/coverage-w05.json` |
| 0.7 : 0.3 | 10,506 | 11.7% | 21.8% | 39.9% | `data/coverage-w70.json` |
| **0.9 : 0.1** | 10,487 | **15.0%** | **27.6%** | **37.6%** | `data/coverage-w09.json` |

> 0.7 실행의 시험 발화 수가 19건 많은 것은, 그 측정이 발화 생성이 완전히 끝나기 직전에
> 시작됐기 때문이다. 결론에 영향을 줄 규모는 아니지만 그대로 기록한다.

## 결론 — 기본값은 0.9

벡터 가중치를 올릴수록 세 지표가 모두 좋아졌다. 특히 **계열사 오분류가 함께 줄었다**는 점이
중요하다. 키워드 일치는 은행·카드·증권에 같은 낱말(`조회`, `이체`, `한도`)이 흩어져 있어
계열사를 가리지 못하는 반면, 임베딩은 문맥으로 구분한다.

키워드 가중치를 0으로 두지 않은 이유는 따로 있다. **임베딩 호출이 실패하면
`createRouter`는 키워드 검색만으로 폴백**한다(`menu-router.js`). 이 경로가 살아 있어야
LLM 계층이 죽어도 화면이 답을 내놓는다. 0.1은 그 폴백 경로를 유지하기 위한 최소치다.

## 남은 한계

세 값 모두 Top-3가 30%에 못 미친다. 다만 이 지표는 **발화 하나에 정답 메뉴가 정확히 하나**라고
가정하며, 실제로는 같은 목적의 메뉴가 여러 경로·여러 계열사에 존재한다. 독립 LLM 심판으로
다시 재면 적합성 Top-3가 95.6%다(`data/relevance-report.json`, 스펙 7-A절).

즉 이 표는 **가중치 사이의 상대 비교**로는 유효하지만, 절대 성능의 척도로 읽으면 안 된다.
